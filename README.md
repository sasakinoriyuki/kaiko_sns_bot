## 日付・時刻と蚕の名前を付ける

`configureNamedCommentary` を1回実行すると、次のような投稿になります。

```text
2026/11/08 14:59
こはく：葉っぱのそばなら、ぼくものんびりできるな。
```

かわいい名前を50個用意し、投稿の成功応答ごとに次の名前へ進みます。名前は後からスクリプトプロパティで変更できます。
日時は送信直前の日本時間を分まで表示します。Geminiの追加呼出しはありません。名前は実況用のニックネームとして順番に使い、画像から個体を識別する機能はありません。
投稿しない確認は `previewPreparedComment`、導入・名簿・設定方法は[名前付きコメントの使い方](名前付きコメントの使い方.md)を参照してください。

## 写真UIに合わせた気持ちを作る

画像の令・日目・温度・湿度を読み、提供された飼育目安と照合します。例えば1〜3令の27〜29℃で「暑い」、湿度の目安との差だけで「ジメジメ」とする文は投稿を見送ります。総日数しか分からない場合に令を決めつけません。
本文は「ぼく」「わたし」などの一人称と、本人の気持ち・願望・好みを含む形に限定します。本人の胸の中で完結する独白にし、視聴者への呼びかけ・閲覧確認・配信のお礼を生成候補にしません。問いかけは本人の好みや願望についての自問です。「みんな」「仲間」は飼育場所に写る仲間の蚕を指します。明確な心の声で一人称だけが省略された場合は「ぼく、」を補い、解説文や数字だけの文には補いません。「蚕たちは〜」「写真では〜」などの観察者目線や、温湿度だけの読み上げは投稿前に見送ります。気持ちの視点は12種類に増やし、食事・温湿度ばかりに偏らないように指示します。判定の目安・読取り結果・更新手順は[飼育目安と実況文](飼育目安と実況文.md)にまとめています。

## 掃除に偏らず、写真に合う気持ちにする

- 20〜45文字を目安に、写真で見える特徴を一つ選び、短い自然な心の声にします。本文の上限は70文字です。
- 過去の実況は比較用です。「ひとり」「隔離」「掃除後の再会・引っ越し」といった設定を現在の事実として引き継ぎません。こうした物語は本文検査でも見送ります。
- 掃除の話題は、画像UIの `cleaningStatusText` で清掃中と確認できた場合に限ります。さらに直近8件の採用済み生成文に掃除関連があれば、今回は別の話題にします。変化モードが無効でもこの間隔を確認します。
- 条件に合わない文は投稿しません。分担モードの自動実行では、数分後に別の実行で再解析を最大2回予約します。手動実行では自動予約しません。

`previewPreparedComment` は保存済みの本文の表示確認です。連打しても本文や名前の順番は変わりません。ログの「本文の解析日時」で、いつ生成した本文か確認できます。
新しい文は学校側で `analyzeLatestImageAndLog` を実行して準備します。手動更新は前回のAPI試行から1分以上空ければ、同じ写真でも記録済みの本文を再解析できます。待機時は次に実行できる日本時間と残り秒数を表示します。手動分も同じ日次予算を消費し、上限やAPIの待機制限は維持します。毎時の更新と文章の変化を使うには `configureHourlyCommentary` を一度実行し、学校・個人のトリガーを1時間にします。

今回の更新では旧形式の本文・プレビューを再利用せず、新しい本文検査を通った解析を待ちます。使用済み予算と投稿結果は維持します。

## 1円玉は大きさ比較の目印として、たまに触れる

1円玉・コインは「今の蚕の体がどのくらいの大きさか」を伝える目印です。寝床・台座・お気に入りの場所として実況しません。
コインの話題の間には、別の話題のYouTube投稿が**4回以上成功**することを必須にします。名前・日時・言い回しを変えても連続投稿は許可せず、「銀色の台座」「つるつるした金属」なども確認します。

飼育領域に硬貨の実物が見える場合だけ、同じGemini応答の `coinReferenceText` に短い根拠を返し、大きさ比較に一言だけ使えます。画像内の過去チャットの文字は根拠にしません。画像1枚から過去より成長したことや、実際の体長・倍率は断定しません。

更新後はまず他の話題から始まり、その投稿成功を確認してからコインの話題を使えるようになります。プレビュー・解析だけでは投稿間隔を進めません。同じ実行内での連続再生成は行わず、自動運用では回数を限って次の解析を予約します。[判定と更新の詳しい説明](飼育目安と実況文.md#1円玉を主役にせず大きさ比較に使う)を参照してください。

## 現在の使い方

| 担当 | すること | 自動実行する関数 |
| --- | --- | --- |
| 学校アカウント | Driveの写真 → Geminiで実況作成 → 蚕ログに保存 | `analyzeLatestImageAndLog` |
| 個人アカウント | GAS内の準備済み実況文 → YouTube投稿 | `postPreparedCommentToYouTube` |

同じGASを個人へ編集共有して使います。個人側に画像フォルダ・スプレッドシートのアクセス権は不要です。

`configureSplitAccountMode` と `configureHourlyCommentary` を実行した運用は次の設定です。

- 学校・個人の専用トリガーは**それぞれ1時間**。作成は各アカウントで1回行います。
- 同じ写真でも新しい実況を生成。直近8件を参考に、着眼点・書き出し・語尾・文体を変えるよう指示します。
- 完全一致や文字の並びが近い実況は見送ります。個人側は前の文を繰り返しません。
- 失敗時は各担当で初回＋最大2回、60分の時間枠内で再試行します。解析待ち・ロック競合で投稿側が先に動いた場合も再確認します。
- GeminiのBOT予算は**72試行/日**。通常は毎時1回で約24試行、残りは失敗時の再試行用です。プレビュー・手動更新・失敗・類似文の見送りも同じ枠を使います。
- 投稿成功後は、自動再試行でも `YOUTUBE_MIN_INTERVAL_MINUTES=60` を守ります。遅れて投稿した直後に次の毎時処理が来ても、続けて投稿しません。
- X・Instagramは無効です。

**コードの貼り替えだけでは、既存の30分トリガーは1時間に変わりません。** [更新手順](使い方ガイド.md)に従って作り直します。
失敗時だけ `retrySchoolAnalysis` / `retryPersonalYouTube` という一度限りの予約が自動で作られます。自分で追加する必要はありません。停止用の `removeBotTriggers` は、自分の通常予約と再試行予約を削除します。
実行時刻・学校と個人の処理順は保証されず、予算・類似文・配信状況・外部サービスの障害によって投稿が1時間以上空く場合があります。[再試行の条件](モデルと利用制限.md#自動再試行の動き)を参照してください。

このBOTが送るのはライブチャットの文章です。写真の撮影・Drive同期・配信開始はPC側で行います。AIの実況は擬人化した想像で、健康状態の診断ではありません。

## 写真と記録の動き

写真は、設定したOBSフォルダ直下のPNG/JPEGを優先します。直下に画像がない場合だけ、直下の `YYYY-MM-DD` フォルダを新しい日付順に探します。空フォルダは飛ばし、画像がある最新の日付フォルダ内で、更新日時が最新の1枚を使います。さらに下の階層や一般名の子フォルダは探しません。

画像は5 MiB以下。古い画像も使います。ファイルの移動やコピーは行いません。
実況は70文字以内で、読み取れない数値・写真から分からない成長や動作の変化を作らないよう指示します。

「蚕ログ」には **日時・画像ファイル名・蚕の気持ち・処理ID** の4列を記録します。
変化モードの日時は解析した時刻（日本時間）で、同じ写真でも新しい実況ごとに1行保存します。以前の行の日時はそのまま残ります。
保存が完了した文を個人側が投稿します。

見るときは「日付別ログ」のB3で日付を選びます。このタブは**シート側の設定**なので、別のスプレッドシートには[作成手順](日付別ログの設定.md)を反映してください。

## 配信先を自動で切り替える

最新版をGASへ貼り替えた後、個人側で **`configureAutoYouTubeLive` を1回実行**します。
登録済みの `CHANNEL_ID` を使い、古い固定設定 `YOUTUBE_VIDEO_ID` を解除します。
チャンネル未登録時は以前の運用の既定ID `UCJ12W_V5k49jE0M38L32Ylg` を使います。配信元が不確かな場合は、下の `configureAutoYouTubeLiveFromVideo` で現在の動画から登録してください。

その後は、配信URLが変わっても動画IDの更新は不要です。
同じチャンネルで配信中の候補を確認し、開始時刻が最新のライブを選びます。配信前・終了済みは投稿対象にしません。最新ライブのチャットが無効なら投稿を待ちます。
確認は既存のトリガーで行い、1時間設定ならその周期で動きます。別アカウントの配信を探すAPI検索は最短60分に1回です。

個人側の `previewYouTubeConnection` は投稿せず、検出した動画URLをログへ表示します。
自動検出でも見つからない場合は、今の動画IDを `YOUTUBE_VIDEO_ID` に一度だけ登録し、個人側で **`configureAutoYouTubeLiveFromVideo`** を実行します。動画情報から `CHANNEL_ID` を登録し、動画固定を解除します。配信中なら、その動画を初期候補として保存してから検証します。

別アカウントで検索・保存済み候補から配信中を取得できなかった場合は、対象チャンネルの動画一覧を直近50件まで補助確認します。検索待ち時間もログへ表示し、検索間隔はリセットしません。
Google公式も[検索インデックスの反映遅れ](https://developers.google.com/youtube/data/reference/rest/v3/search/list#order)を説明しています。
対象はそのアカウントでAPIから取得できる動画です。限定公開・非公開は検索に出ないため、配信所有者の権限または固定IDが必要になる場合があります。
[かんたん操作ガイド](使い方ガイド.md)に更新手順があります。認証情報・解析済み文・投稿結果・使用済み予算・トリガーの間隔は変更しません。

## 投稿が止まったとき

- Gemini HTTP 503：一時的な混雑・障害を示す応答です。モデル変更やキー交換が必須という意味ではありません。新版の分担用自動実行は、APIの待機指示を守って最大2回再試行します。[最新版への更新手順](使い方ガイド.md)で72試行設定と各アカウントの専用トリガーを反映してください。
- ライブチャットが見つからない：`CHANNEL_ID` が配信しているチャンネルか確認し、`configureAutoYouTubeLive` → `previewYouTubeConnection` を実行します。配信中・チャット有効・個人アカウントからアクセスできることも必要です。
- 一人称チェックで止まる：新版では不採用の理由コードと候補文をログへ表示します。一人称だけを省略した明確な心の声は補完します。観察者文は引き続き見送ります。

詳しくは[かんたん操作ガイド](使い方ガイド.md)の「ログで投稿が止まるとき」を参照してください。
`configureSplitAccountMode` は既存の投稿先を維持します。古い動画への固定を解除するのは `configureAutoYouTubeLive` です。

## 配信を検出できないとき

`diagnosePersonalYouTube` は投稿せず確認します。「解析データ: 準備済み」「投稿状態: pending」「投稿用チャンネル: 取得済み」で、配信チャットだけ取得できない場合は、ライブの検出を調べます。

| 自動検出のログ | 意味・確認すること |
| --- | --- |
| ライブ検索待ち：次の検索まで約○分 | 検索間隔の待機。検索時刻をリセットせず待つ |
| ライブ検索結果：動画候補0件 | 検索から見つからず、チャンネルの動画一覧も補助確認する |
| 対象チャンネル名 | 目的の配信者と一致するか確認 |
| 対象チャンネルを取得できません | `CHANNEL_ID` とアクセス権を確認 |
| 動画候補の確認・候補の内訳 | 別チャンネル、通常動画、開始未確認、終了済みを区別 |
| 配信中動画：チャットIDなし | 配信のチャット設定・個人アカウントのアクセスを確認 |

補助確認はAPIで取得できる直近50件です。限定公開・非公開は検索に出ないため、配信所有者の権限か固定IDが必要になる場合があります。

同じGASを共有しているので、設定値は学校・個人のどちらで変更しても反映されます。
特定動画へ固定したい場合だけ、URLの `v=` の後ろ11文字を `YOUTUBE_VIDEO_ID` に保存します。**固定中は配信URLが変わるたびに動画IDの変更が必要**です。
固定動画の確認では、次の詳細ログも表示します。

| 新しいログ | 確認すること |
| --- | --- |
| 配信終了済み | `configureAutoYouTubeLive` で自動検出に戻すか、固定する動画IDを変更 |
| 配信開始を確認できません | 配信前・APIへの反映待ちを含むため、実際の配信状態を確認 |
| 配信開始済み・チャットIDなし | チャットの有効化、配信設定、個人アカウントからのアクセスを確認 |
| 動画を取得できません | 動画IDと公開範囲、個人アカウントでその動画を開けるかを確認 |
| ライブ配信情報なし | 通常動画ではなく、ライブ配信のIDかを確認 |

## GASへの導入

本体は[コード.gs](コード.gs)、サービス・権限設定は[appsscript.json](appsscript.json)です。
[初期設定の10手順](アカウント分担の使い方.md)で、アカウント準備、共有、キー、保存先、投稿テスト、自動実行まで説明しています。

APIキーは「プロジェクトの設定 → スクリプト プロパティ」に保存します。
ソースに残っている既定の保存先・配信先は以前の運用用です。自分用に初めて作る場合は、自分のフォルダ・スプレッドシート・配信チャンネルのIDを指定します。
GASの編集者は登録済みキーと共有状態を読めます。[Google公式：設定の共有範囲](https://developers.google.com/apps-script/guides/properties)

### スクリプト プロパティ

**普段は登録済みの値を使います。** `true` / `false` は半角小文字です。
次の表は参照用です。「1時間設定後」は `configureHourlyCommentary` を実行した値を示します。

| 名前 | 値・コード単体の初期値 | 用途 |
| --- | --- | --- |
| `GEMINI_API_KEY` | 必須 | Google AI Studioで発行したGemini APIキー |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | 固定モデルID。latest・preview名は拒否。無料提供と利用可否はプロジェクト側で確認 |
| `FOLDER_ID` | 初回は自分のIDを指定 | OBSなどの親フォルダ。直下を優先し、画像なしなら直下のYYYY-MM-DDフォルダを新しい日付順に探す |
| `SPREADSHEET_ID` | 初回は自分のIDを指定 | 履歴の保存先 |
| `CHANNEL_ID` | 自分用に作る場合は配信チャンネルのIDを指定 | 自動検出の対象。`UC`で始まる24文字 |
| `LOG_SHEET_NAME` | `蚕ログ` | 専用のログシート。既存の最初のシートは変更しない |
| `DRY_RUN` | `true` | `true`では推論・配信確認のみ。投稿と履歴保存を有効にするには`false` |
| `SPLIT_ACCOUNT_MODE` | 分担設定後 `true`（単体の初期値は `false`） | 学校と個人の分担モード。専用関数・トリガーは分担ガイド参照 |
| `ENABLE_NAMED_COMMENTS` | 名前設定後 `true`（単体の初期値は `false`） | 日本時間の日時・名前付きのYouTube投稿 |
| `SILKWORM_NAMES` | 名前設定時に50個のJSON配列を登録 | 1〜100個、各1〜12文字。順番に使用 |
| `ENABLE_REARING_CONTEXT` | `true` | 写真UIと飼育目安を反映。旧互換モードの検証以外では有効を維持 |
| `ENABLE_FEELING_VARIATION` | 1時間設定後 `true`（単体の初期値は `false`） | `configureHourlyCommentary` で有効化。同じ写真も再解析し、似た実況・同じ文の再投稿を抑制 |
| `YOUTUBE_VIDEO_ID` | 未指定 | 通常は空で自動検出。特定の動画に固定する場合だけ11文字のIDを指定 |
| `ENABLE_X` | `false` | YouTubeだけなら変更不要。Xも使用する場合は`true` |
| `ENABLE_INSTAGRAM` | `false` | Instagram画像フィード投稿を有効にする場合は`true` |
| `INSTAGRAM_USER_ID` | Instagram有効時に必須 | Instagram Loginで取得した投稿先の数値ID |
| `INSTAGRAM_ACCESS_TOKEN` | Instagram有効時に必須 | Instagram User access token（basic・content_publish権限） |
| `INSTAGRAM_IMAGE_URL_TEMPLATE` | Instagram有効時に必須 | `{digest}` を含む公開HTTPS JPEG URL。`{fileId}` も利用可能 |
| `INSTAGRAM_API_VERSION` | `v25.0` | Instagram APIの固定バージョン |
| `INSTAGRAM_DAILY_POST_BUDGET` | `1` | 失敗を含む試行数/UTC日。間隔も `24時間 / 予算` 以上 |
| `LIVE_SEARCH_INTERVAL_MINUTES` | `60` | 他アカウントから配信を探す場合の検索間隔。60以上 |
| `GEMINI_DAILY_REQUEST_BUDGET` | 1時間設定後 `72`（単体の初期値は `48`） | 失敗・プレビューを含む試行数/日。自動実行はトリガー周期、学校の手動更新は最短1分。その他の手動解析は最短10分と `1440 / 予算` の長い方 |
| `YOUTUBE_MIN_INTERVAL_MINUTES` | 1時間設定後 `60`（単体の初期値は `30`） | 手動・分担モード自動実行の最短投稿間隔。10以上。自動実行の周期はトリガーで指定し、投稿済みならこの間隔も守る |
| `YOUTUBE_DAILY_UNIT_BUDGET` | `8000` | YouTube APIの予約単位/日。予約に使うコスト前提は計算資料に記載 |
| `X_MIN_INTERVAL_MINUTES` | `30` | 最短投稿間隔。30以上。日次予算の均等配分でさらに長くなる |
| `X_DAILY_POST_BUDGET` | `1` | アップロード・投稿を含む試行数/日 |
| `X_31DAY_POST_BUDGET` | `40` | 直近31日分の試行上限。日次境界を含め保守的に集計 |
| `TWITTER_API_KEY` | X有効時に必須 | XのConsumer/API Key |
| `TWITTER_API_SECRET` | X有効時に必須 | XのConsumer/API Key Secret |
| `TWITTER_ACCESS_TOKEN` | X有効時に必須 | 投稿ユーザーのOAuth 1.0a Access Token |
| `TWITTER_ACCESS_SECRET` | X有効時に必須 | 投稿ユーザーのAccess Token Secret |

通常は `YOUTUBE_VIDEO_ID` を登録せず、`CHANNEL_ID` で自動検出します。特定動画に固定したい場合だけ、配信URLの `v=` の後ろ11文字を `YOUTUBE_VIDEO_ID` に指定します。固定中は自動で別動画へ切り替わりません。
`GEMINI_MODEL` の利用可否・料金・割当は、実行するプロジェクトで確認してください。

### 投稿結果が不明になった場合

`unknown` は、送信に成功したか判定できない状態です。二重投稿を避けるため、自動再送・実況の更新を止めます。

1. 学校・個人それぞれで `removeBotTriggers` を実行します。
2. 個人側で実際のライブチャットを確認します。読取診断は `diagnosePersonalYouTube` です。
3. 保存されている実況文が投稿済みか、未投稿かを確かめます。
4. 復旧が必要な場合だけ、管理する人が `YOSAN_STATE_V1` の該当する投稿先の状態を修正します。確認済みの投稿は `sent`、未投稿を確認できた場合は `pending` とし、他の項目は残します。
5. 手動で確認してから、各アカウントの専用トリガーで再開します。

変化モードは、写真が変わってもYouTubeの `unknown` を維持します。
`YOSAN_` で始まる保存値を丸ごと削除すると、重複投稿や制限状態の消失につながります。普段の操作では変更しません。

| 保存される状態 | 意味 |
| --- | --- |
| `pending` | 未投稿・条件を満たすまで待機 |
| `sending` | 送信開始前に保存。中断時は次回 `unknown` |
| `sent` | 成功応答を受信。変化モードでは次の新しい文を待つ |
| `unknown` | 成功不明。確認が済むまで再送を停止 |

## 1アカウントで使う場合（詳細設定）

Drive・Sheets・YouTubeを同じアカウントで利用できる場合は、従来の一括処理 `processLatestImageAndLog` も使えます。
`SPLIT_ACCOUNT_MODE=false` とし、`configureHourlyCommentary`、`DRY_RUN=true` での `previewLatestImage`、`DRY_RUN=false` での手動確認の順に進めます。X・Instagramを使用しない場合はそれぞれ無効にします。

自動実行は `installThirtyMinuteTrigger` で作成してから、時計画面で `processLatestImageAndLog` を「時間ベース・1時間」へ変更します。この互換用作成関数自体は30分です。
分担用の2本は併用せず、1アカウントでは一括処理の1本で動かします。
`configureThirtyMinuteYouTube` は従来設定用です。今回の1時間運用は `configureHourlyCommentary` を使います。

## X・Instagramも使う場合

それぞれの導入手順で、アカウント・権限・料金・画像URL・投稿テストを確認してください。Instagramは既存のGemini解析文を使い、初期は有効化後も1試行/日・24時間以上の間隔です。
学校・個人の分担関数はYouTube専用です。X・Instagramの実行は、必要なアクセス権を持つアカウントで一括処理を使う構成になります。
