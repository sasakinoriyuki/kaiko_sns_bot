# 蚕CHANNEL ライブ配信連携BOT（GAS）

Google Driveの最新スクリーンショットをGeminiで読み取り、蚕の「気持ち」を想像した短文をYouTubeライブチャットへ投稿します。X・Instagramへの画像付き投稿も任意で有効にできます。画像を撮影・同期するPC側の処理は、このGASには含みません。

本体は [`コード.gs`](コード.gs)、GASのサービス・権限設定は [`appsscript.json`](appsscript.json) です。元のコードから、フォルダ・スプレッドシート・チャンネルのIDを引き継いでいます。秘密鍵はソースに書きません。

初めて使う場合は、[使い方ガイド](使い方ガイド.md)を読んでください。できること、GASの画面での設定方法、動作確認、自動実行の開始・停止を順番に説明しています。

[モデルと利用制限の計算](モデルと利用制限.md)、[X APIを初めて使う人向けの導入手順](X_API導入手順.md)も追加しています。共有キーの上限が不明なため、初期予算はGemini 48回/日、Xは有効化後も1試行/日です。初期の自動投稿は30分間隔で、以後はGASのトリガー画面から間隔を変更できます。これらはBOTの予算であり、外部APIの無料枠を確認した数値ではありません。

Instagramのアカウント準備・認証・公開画像URL・投稿テストは[導入手順](導入手順.md)を参照してください。初期状態では無効、有効化後も1試行/日・24時間以上の間隔です。既存のGemini解析結果を再利用し、解析対象と同一のJPEGを公開HTTPS URLにも保存します。

## 元コードで直した点

| 問題 | 修正内容 |
| --- | --- |
| `const GEMINI_API_KEY =` が未完成で構文エラー | GASのスクリプト プロパティから取得 |
| 古いモデルや参照先が変わるlatest別名を使用 | 軽量な `gemini-3.5-flash-lite` を初期値に固定。思考を無効にし、出力上限256トークンに変更 |
| 作成日時だけで画像を選び、同じファイルへの上書きを見落とす | 更新日時で選び、ID・更新日時・画像のSHA-256で処理対象を識別 |
| 非画像や空・巨大な画像も対象になる | PNG/JPEGの実データを確認し、5 MiB超・空画像を除外。画像の古さでは見送らない |
| トリガーごとに同じ画像を再推論・再投稿する | ScriptLockと永続状態で同時実行・X・Instagramの同一画像の再投稿を抑制。YouTubeは投稿間隔を空けて再投稿 |
| AI本文中の「エラー」「失敗」もAPI失敗扱い | HTTPステータス、JSON、ブロック理由、終了理由、空回答で判定 |
| シート書き込み失敗後も外部投稿を進める | 記録を完了してから投稿。処理IDで保存直後の中断による履歴重複も抑制 |
| 毎回の `Search.list` で検索クォータを消費 | 所有者アカウントでは `LiveBroadcasts.list`。他アカウントでは検索間隔の制限と動画IDキャッシュ |
| 配信詳細がない場合に例外、配信終了や別チャンネルの確認不足 | チャンネル、実開始時刻、終了時刻、チャットIDを確認 |
| OAuth1の既定処理で画像Blobがフォーム文字列化される | Xの `media_data` をBase64のフォーム形式で署名・送信 |
| `hasAccess()` をAPI権限の検証に使っている | 実際のAPI応答で成否を判断。トークンが存在してもRead/write権限は別 |
| YouTube成功後にXが失敗すると、次回に両方を再投稿 | 投稿先ごとの状態を保存し、成功した側を再送しない |
| 手動実行・エラー再試行が割当を消費する | プレビュー・失敗も試行に数え、最短間隔・日次/31日予算・429待機を永続化 |

## 学校アカウントでYouTubeが制限されている場合

同じGASを個人アカウントへ編集共有し、学校は `analyzeLatestImageAndLog` でDrive・Gemini・Sheetsだけ、個人は `postPreparedCommentToYouTube` で共有済みの実況文だけを投稿できます。個人側にDrive/Sheetsのアクセス権は不要です。具体的な切り替え・認可・2本のトリガー設定は[アカウント分担の使い方](アカウント分担の使い方.md)を参照してください。

`configureSplitAccountMode` で分担モードにすると、旧 `processLatestImageAndLog` も解析のみになります。`YOUTUBE_VIDEO_ID` を指定した場合は、その動画を直接確認します。空なら従来のチャンネル検索を使います。Google側のOAuth・外部共有制限は別途適用されます。

## GASへの導入

1. 対象のGASプロジェクトで、既存の同名関数を含むコードを `コード.gs` の内容に置き換えます。元のトリガーが動作中なら、編集前に停止してください。別のファイルに元の関数・定数を残すと名前が衝突します。
2. 「プロジェクトの設定」でマニフェスト `appsscript.json` を表示し、このリポジトリの設定を反映します。既存プロジェクトのライブラリ・他サービス設定は維持し、`dependencies.enabledAdvancedServices` のYouTube、V8、タイムゾーン、必要な `oauthScopes` を統合してください。
3. 「サービス」で **YouTube Data API v3**、識別子 **YouTube** が追加されていることを確認します。標準Google Cloudプロジェクトを紐付けている場合は、そのプロジェクト側でもYouTube Data API v3を有効にします。
4. 「プロジェクトの設定 > スクリプト プロパティ」に、下記の設定を追加します。キーをチャットやコードに貼る必要はありません。
5. 配信者のYouTubeチャンネルを利用でき、Driveフォルダの閲覧・スプレッドシートの編集も可能なGoogleアカウントで `previewLatestImage()` を手動実行し、権限を許可します。実行ログの短文と配信検出結果を確認してください。プレビューではGemini APIを利用するため、利用料金・割当の対象になります。
6. 問題なければ `DRY_RUN` を `false` に変更し、`processLatestImageAndLog()` を一度実行します。この操作は実際にYouTubeへ投稿します。X・Instagramを有効にした場合はそれらにも投稿します。シートと実際のチャットを確認してください。
7. `installThirtyMinuteTrigger()` を実行すると初期30分の時間主導トリガーを1つ作ります。以後はGAS左の時計「トリガー」→対象の鉛筆→「分ベースのタイマー」で1・5・10・15・30分から選び保存してください。間隔変更のたびに作成関数を実行すると30分へ戻るため、普段の変更はトリガー画面で行います。

### スクリプト プロパティ

| 名前 | 必須・初期値 | 用途 |
| --- | --- | --- |
| `GEMINI_API_KEY` | 必須 | Google AI Studioで発行したGemini APIキー |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | 固定モデルID。latest・preview名は拒否。無料提供と利用可否はプロジェクト側で確認 |
| `FOLDER_ID` | 元コードのフォルダID | OBSなどの親フォルダ。直下を優先し、画像なしなら直下のYYYY-MM-DDフォルダを新しい日付順に探す |
| `SPREADSHEET_ID` | 元コードのスプレッドシートID | 履歴の保存先 |
| `CHANNEL_ID` | `UCJ12W_V5k49jE0M38L32Ylg` | 配信対象チャンネル |
| `LOG_SHEET_NAME` | `蚕ログ` | 専用のログシート。既存の最初のシートは変更しない |
| `DRY_RUN` | `true` | `true`では推論・配信確認のみ。投稿と履歴保存を有効にするには`false` |
| `SPLIT_ACCOUNT_MODE` | `false` | 学校と個人の分担モード。専用関数・トリガーは分担ガイド参照 |
| `YOUTUBE_VIDEO_ID` | 未指定 | 指定動画を直接確認する11文字のID。空ならチャンネルの自動検出 |
| `ENABLE_X` | `false` | YouTubeだけなら変更不要。Xも使用する場合は`true` |
| `ENABLE_INSTAGRAM` | `false` | Instagram画像フィード投稿を有効にする場合は`true` |
| `INSTAGRAM_USER_ID` | Instagram有効時に必須 | Instagram Loginで取得した投稿先の数値ID |
| `INSTAGRAM_ACCESS_TOKEN` | Instagram有効時に必須 | Instagram User access token（basic・content_publish権限） |
| `INSTAGRAM_IMAGE_URL_TEMPLATE` | Instagram有効時に必須 | `{digest}` を含む公開HTTPS JPEG URL。`{fileId}` も利用可能 |
| `INSTAGRAM_API_VERSION` | `v25.0` | Instagram APIの固定バージョン |
| `INSTAGRAM_DAILY_POST_BUDGET` | `1` | 失敗を含む試行数/UTC日。間隔も `24時間 / 予算` 以上 |
| `LIVE_SEARCH_INTERVAL_MINUTES` | `60` | 他アカウントから配信を探す場合の検索間隔。60以上 |
| `GEMINI_DAILY_REQUEST_BUDGET` | `48` | 失敗・プレビューを含む試行数/日。自動実行はトリガー周期、手動実行は最短10分と `1440 / 予算` の長い方 |
| `YOUTUBE_MIN_INTERVAL_MINUTES` | `30` | 手動実行の最短投稿間隔。10以上。自動投稿はトリガーの間隔で動く |
| `YOUTUBE_DAILY_UNIT_BUDGET` | `8000` | YouTube APIの予約単位/日。予約に使うコスト前提は計算資料に記載 |
| `X_MIN_INTERVAL_MINUTES` | `30` | 最短投稿間隔。30以上。日次予算の均等配分でさらに長くなる |
| `X_DAILY_POST_BUDGET` | `1` | アップロード・投稿を含む試行数/日 |
| `X_31DAY_POST_BUDGET` | `40` | 直近31日分の試行上限。日次境界を含め保守的に集計 |
| `TWITTER_API_KEY` | X有効時に必須 | XのConsumer/API Key |
| `TWITTER_API_SECRET` | X有効時に必須 | XのConsumer/API Key Secret |
| `TWITTER_ACCESS_TOKEN` | X有効時に必須 | 投稿ユーザーのOAuth 1.0a Access Token |
| `TWITTER_ACCESS_SECRET` | X有効時に必須 | 投稿ユーザーのAccess Token Secret |

真偽値は小文字の `true` / `false` を指定します。ソースに含まれるIDは認証情報ではありませんが、アクセス権は実行アカウントに必要です。スクリプト プロパティはプロジェクトの編集者が読めるため、編集権限も適切に管理してください。

以前 `GEMINI_MODEL=gemini-flash-latest` を登録した場合は、固定ID `gemini-3.5-flash-lite` に変更するか、モデルのプロパティだけを削除して新しい初期値を使ってください。実際の利用可否は `previewLatestImage()` で確認します。現在の無料枠・料金の数値は未確認であり、共有キーの持ち主の利用も同じ枠に含まれます。利用不可ならHTTPエラーとなり記録・投稿しません。

### Xも利用する場合

登録から始める場合は、[X API導入手順](X_API導入手順.md)を参照してください。現在の無料プランの有無・エンドポイントの利用条件は、申し込み画面で確認してください。

X Developer Portalでアプリに **Read and write** を付与し、その権限でユーザーのAccess Token / Secretを発行します。権限変更前のトークンを使っていた場合は再生成します。画像アップロードと投稿の両エンドポイントが、契約中のAPIプラン・割当で利用可能である必要があります。

GASの「ライブラリ」に、公式 **OAuth1** を追加します。

- 公式README記載のスクリプトID: `1CXDCY5sqT9ph64fFwSzVtXnbjpSfWdRymafDrtIZ7Z_hwysTY7IIhi7s`
- 識別子: `OAuth1`
- バージョン: 導入時に利用できる公開版を選択し、開発モードは使用しない

依頼文のライブラリIDは、確認した公式OAuth1のREADMEに記載されたIDと異なります。上記の公式IDを使用してください。YouTubeだけを使う場合は、OAuth1ライブラリとXのキーは不要です。リポジトリのマニフェストには、Xを任意にするためOAuth1の依存を固定していません。

## トリガー画面で自動投稿の間隔を変更する

GASのコードを更新後、`configureThirtyMinuteYouTube()` を1回実行すると、既存プロパティを手動実行の投稿間隔30分・Gemini予算48試行/日に変更できます。認証情報、投稿状態、使用済み予算は維持します。旧 `MAX_IMAGE_AGE_MINUTES` は廃止し、保存されていても参照しません。

YouTubeは時間主導トリガーが動くたびに、画像が変わらなくても同じ解析文を投稿します（初期30分）。画像が同じならGemini解析と履歴保存は繰り返しません。投稿結果が不明な `unknown` は自動再送しません。自動実行では固定の30分制限を使いませんが、連続発火は最短1分で抑制します。APIの日次予算・配信状況により投稿を待機する場合があります。間隔変更だけではGeminiの1日予算は増えません。

## 運用上の挙動

画像は、指定したOBSフォルダの直下を優先します。直下にPNG/JPEGがない場合だけ、`2026-10-31` のような実在する日付名（`YYYY-MM-DD`）の直下の子フォルダを新しい日付順に探します。空・非画像のみの日付フォルダは飛ばし、画像がある最新の日付フォルダ内で更新日時が最新の1枚を選びます。日付フォルダの更新日時ではなく名前の日付で順序を決め、一般名のフォルダや、さらに下の階層は探しません。直下に画像がある場合は古くても優先し、画像の古さによる投稿見送りは行いません。画像ファイルの移動・コピーは行いません。

- 推論結果は「蚕ログ」の2行目へ `[画像更新日時（日本時間）, 画像ファイル名, 蚕の気持ち, 処理ID]` として挿入します。4列目は履歴の重複防止用です。シートがなければ作成します。既存の同名シートの見出しが異なる場合は上書きせず停止するため、別の `LOG_SHEET_NAME` を指定してください。
- 設定したトリガー間隔で、予算を確認して最新の画像を選びます。初期は30分で、新しい画像の解析は1日48試行までです。1分ごとの画像をすべて処理する方式ではありません。新しい画像へ進むと、以前の画像の未投稿分は自動追跡しません。
- 配信チャンネルの所有者として認可されていれば、各処理でアクティブな配信を取得し、開始時刻が最も新しいものを選びます。複数同時配信にも対応します。
- 他のアカウントで実行する場合、取得済み配信の継続を `Videos.list` で毎回確認し、新規検索は1時間ごとです。その場合、新規・切り替わった配信の検出は最大約60分遅れる可能性があります。10分ごとの検出が必要なら、対象チャンネルの所有者として認可してください。YouTubeの認可チャンネルと実際の投稿権限は、本番で確認が必要です。
- ライブがない、配信が終了した、チャットが無効、という場合はYouTube投稿を待機します。履歴と、有効になっているX連携は独立して処理します。Xのリンク文は、ライブ配信中と断定しない表現です。
- ファイルIDまたは更新日時が変わった画像は、新しい処理対象です。同じ画面が別ファイルとしてアップロードされれば、新しい画像として扱います。
- Geminiの429は次のPacific日次境界とAPIの待機指示の遅い方まで停止します。5xxも即時リトライせず待機します。Xの429・レート残量・resetヘッダーも反映し、同じ文面の連続投稿を見送ります。日本語の短文は70文字以内に制限します。
- 予算と待機時刻は `YOSAN_LIMITS_V1`、プレビューの解析キャッシュは `YOSAN_PREVIEW_V1` に保存します。同じ画像のプレビュー結果は本番でも再利用します。`showBotUsage()` で、秘密鍵を表示せずBOTの予約済み試行数と直近の実トークン数を確認できます。

### Instagramも利用する場合

[導入手順](導入手順.md)に従い、Instagram API with Instagram Loginのプロアカウントと公開JPEG URLを準備します。プレビューではInstagramへアクセスしません。投稿コンテナを保存して準備完了後に公開し、結果が不明なら自動再送を止めます。コンテナの `ERROR`・`EXPIRED` は `failed` として停止します。公開サーバーへのアップロードとトークン更新は別途必要です。

### 投稿結果が不明になった場合

GASのスクリプト プロパティ `YOSAN_STATE_V1` に、最新画像の推論結果・履歴保存済みフラグ・投稿先ごとの状態が保存されます。

| 状態 | 意味 |
| --- | --- |
| `pending` | 未投稿。最新画像が変わる前で、間隔・予算・待機条件を満たせば次回の実行で再試行可能 |
| `sending` | 投稿直前に保存した状態。実行が中断した場合、次回は`unknown`扱い |
| `sent` | 成功応答を取得済み。YouTubeは投稿間隔後に同じ画像でも再投稿。X・Instagramは同じ画像を再送しない |
| `unknown` | タイムアウト、5xx、YouTube投稿の例外などで成功したか不明。二重投稿を避けるため同じ画像を自動再送しない |

YouTube・X・Instagramには、このGASが利用できる共通の投稿・状態保存トランザクションがありません。厳密な「必ず一度だけの配信」は保証できず、応答が不明な場合は自動再送を止める設計です。Xの明確な4xx拒否（408を除く）は `pending` に戻します。

復旧するときは `removeBotTriggers()` で停止し、実際のチャット・X・Instagramを確認してください。**まだ保存状態と同じ画像を再処理する必要がある場合に限り**、未投稿を確認した側の状態を `pending`、投稿済みを確認した側を `sent` に修正します。他のフィールドは維持します。状態を丸ごと削除すると、推論・投稿をやり直して重複する可能性があります。新しい画像への切り替え後は、通常の処理に任せてください。

トリガーを停止したい場合は `removeBotTriggers()` を実行します。この関数は実行アカウントのBOT用トリガーだけを削除します。

## 開発時のテスト

Node.js 22以上で、追加パッケージのインストールなしに実行できます。

```sh
cd kaiko_sns_bot
npm test
```

GAS・Gemini・YouTube・X・Instagramのサービスをモックし、本体をNodeのVMで実行します。重複防止、上書き画像、古い画像、API失敗、部分成功、状態保存失敗、履歴保存直後の中断、配信の切り替え、プレビュー、トリガー管理などを検証します。外部への投稿や実際の秘密鍵は使用しません。GAS上の認可、Drive/Sheetsへの実アクセス、モデルの利用可否、実際の投稿は、このローカルテストでは検証していません。

古い画像の処理・同じ画像の30分投稿を含む合計106件はV8上のNode API互換実行で通過しました。クラウド環境の起動失敗により `npm test` は未実行です。実アカウントへの投稿は行っていません。
